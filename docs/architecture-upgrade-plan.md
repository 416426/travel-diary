# travel-diary 架构升级规划（先 A 后 B）

> 状态：📋 已定稿待执行（2026-07-31）· 当前版本 v0.1 纯静态
> 决策：先轻量渐进式（Serverless 前后端分离），后容器化部署

---

## 1. 现状分析

| 维度 | 现状 |
|------|------|
| 架构 | 纯静态：HTML + JS + JSON，Leaflet CDN 地图 |
| 托管 | GitHub Pages（自定义域名 blog.hubai.top） |
| 数据 | `data/*.json` 文件，手动编辑 |
| 照片 | `photos/` 目录 + 导入页压缩（≤1MB/2048px） |
| 成本 | ¥0（除模型 API 消耗） |
| 优势 | 零依赖、零运维、秒级更新、免费 |
| 瓶颈 | 无后端能力（上传/评论/管理后台/搜索/用户系统均不可做）；照片无对象存储 |

## 2. 升级目标

```
阶段 A（近期）：Serverless 前后端分离 —— 零安装、零成本
阶段 B（远期）：容器化部署 —— Docker + VPS，私有化/商用级

前端（保留静态 or 框架化）→ API 层 → 数据层
```

## 3. 阶段 A：轻量渐进式（Serverless）

### 3.1 目标架构

```
GitHub Pages（前端静态：现状保留）
      │  HTTPS + CORS
      ▼
Cloudflare Workers / Pages Functions（API 层，免费额度）
      │
      ▼
Cloudflare D1 (SQLite) / KV —— 结构化数据
      │
      ▼
R2 对象存储 —— 照片原图（免费 10GB）
```

### 3.2 能获得的能力

| 能力 | 说明 |
|------|------|
| 📤 真·照片上传 | 网页直接传图到 R2，不再手动放文件夹 |
| 💬 评论/留言 | D1 数据库存储 |
| 🔍 全文搜索 | 笔记/旅行条目搜索 |
| 🛠️ 管理后台 | 网页端增删改旅行条目（不再改 JSON） |
| 👤 用户系统 | 可选（Cloudflare 支持 JWT/session） |
| 📊 数据统计 | 访问量/照片热度 |

### 3.3 依赖与成本

| 项 | 说明 | 成本 |
|----|------|:----:|
| Cloudflare 账号 | 免费注册 | ¥0 |
| Workers 免费额度 | 10 万请求/天 | ¥0 |
| D1 数据库 | 5GB 存储 | ¥0 |
| R2 对象存储 | 10GB 存储 + 100 万读/月 | ¥0 |
| **安装需求** | **无**（全部云端配置，本地仅 git/wrangler CLI 需批准后安装或用网页控制台） | — |

> ⚠️ wrangler CLI 需 npm 安装 → 违反安全规则 → **需用户批准提权**；或全程用 Cloudflare 网页控制台（零安装）

### 3.4 迁移步骤（预留）

1. 数据 `trips.json/notes.json/profile.json` → 导入 D1 表结构
2. 前端 fetch 改为调用 API（保留 JSON 直读作为降级回退）
3. 照片墙 → R2 签名 URL；旧照片批量上传 R2
4. 导入页 → 改为直传 R2（保留本地压缩逻辑）
5. 地图/倒计时/笔记逻辑不变

## 4. 阶段 B：容器化部署（远期）

### 4.1 目标架构

```
┌─ Docker Compose ─────────────────────────┐
│  nginx（前端 + 反向代理 + HTTPS）         │
│  api（FastAPI/Node，REST API）           │
│  postgres（PostgreSQL 数据库）           │
│  redis（缓存，可选）                     │
│  minio（对象存储，自托管 S3 兼容）        │
└──────────────────────────────────────────┘
        │
        ▼
   VPS / 云服务器（2C2G 起，¥30-80/月）
```

### 4.2 前置条件（必须满足才启动）

| 条件 | 说明 |
|------|------|
| ✅ 用户批准安装 Docker | 安全规则第 1 条豁免（brew/官方安装器） |
| ✅ 预算确认 | VPS ¥30-80/月 + 域名续费 |
| ✅ 阶段 A 已稳定运行 | 先验证前后端分离逻辑，再容器化 |
| ✅ 访问量或功能需求驱动 | 有明确升级理由，不为升级而升级 |

### 4.3 技术选型（建议）

| 层 | 选项 | 推荐 |
|----|------|------|
| 前端 | Vue 3 / React / 保留原生 | 保留原生（成本最低）或 Vue 3 |
| 后端 | FastAPI (Python) / Node (Express/Nest) | FastAPI（Python 生态 + 一人公司员工熟悉） |
| 数据库 | PostgreSQL | ✅ |
| 缓存 | Redis（可选） | 后续按需 |
| 存储 | MinIO（S3 兼容） | ✅ 私有化 |
| 反向代理 | Nginx / Caddy | Caddy（自动 HTTPS，配置简单） |

## 5. 数据迁移方案（A→B 通用）

```
JSON 文件 → D1（阶段 A）→ PostgreSQL（阶段 B）
原则：数据永远可导出为 JSON（保留 git 历史作为最终兜底）
```

| 数据 | 表/集合 | 关键字段 |
|------|---------|----------|
| 旅行 | trips | id, title, date, lat, lng, mood, thoughts, photos[], highlights[] |
| 笔记 | notes | id, title, category, tags, content |
| 档案 | profile | name, bio, nextTrip |
| 照片 | photos | key, trip_id, gps, size, created_at |

## 7. 触发条件（A → B 升级判断）

满足任意 2 条即考虑升级 B：
1. 月访问量 > 10 万（Workers 免费额度吃紧）
2. 需要私有数据/自托管合规（照片不想放第三方云）
3. 需要重型计算（图片处理、AI 分析照片）
4. 想把项目做成可商用/可分享产品

## 8. 风险与回退

| 风险 | 缓解 |
|------|------|
| Serverless 冷启动延迟 | Workers 冷启动 <50ms，影响可忽略 |
| Cloudflare 服务变更/涨价 | 数据可导出，随时迁移 |
| 容器化运维复杂度 | 保留阶段 A 架构直到 B 稳定；git 双分支 |
| 升级过程中断服务 | 静态站保留，新架构并行灰度 |
| **回退方案** | 任何时候可回退到纯静态（数据导出 JSON 即恢复） |

## 9. 模型使用策略（贯穿升级）
